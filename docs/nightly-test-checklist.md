# Forward Quickstart 完整测试清单与夜间巡检手册

适用项目：本仓库的 Forward Quickstart Demo。本文用于后续接入每天凌晨 3 点的巡检和告警，**不是已运行的定时任务，也不是一条可运行所有项目的脚本**。

## 1. 测试分层与合格口径

| 层级 | 要验证什么 | 当前怎么执行 | 夜间建议 |
| --- | --- | --- | --- |
| A：代码与构建 | ESLint、单元测试、类型检查、产物构建 | 仓库已有 npm 命令，无需真实凭据 | 必跑；失败即判失败 |
| B：接口与部署入口 | 真实 SDK 经 HTTP/SSE/WebSocket 代理与模拟上游交互；对照本地与 Vercel 入口 | 仓库已提供服务端测试和 `test:deployment` | 必跑；并不等于线上部署验收 |
| C：浏览器回归 | 从点击、请求到数据显示或错误提示，覆盖表单、历史、下载和异步竞态 | 可用 `remote-browser-use` 在本地页面进行模拟上游验收；**尚无仓库级无人值守 E2E 命令** | 接入专用浏览器运行器和固定夹具后设为必跑；接入前报告未覆盖，不记为通过 |
| D：真实上游冒烟 | 实际部署、账号权限、区域、配额、Beta 和外部集成 | 需测试环境、专用账号、独立授权与凭据；本文未启用 | 可选；先只读，受控写入单独开启。未配置或未授权标记跳过 |

**结果定义：**每条用例记录 `PASS`、`FAIL`、`SKIP` 或 `BLOCKED`。必跑用例 `FAIL` 则整轮失败；必跑用例无结果、因依赖失败未运行或环境不可用，判为阻塞/未完成，不能发“全部通过”。可选项跳过必须注明原因。A/B 通过只说明离线回归通过，不能代表 C/D 通过。

## 2. 每日执行顺序

### 2.1 准备与隔离

- 调度时间设为每天 `03:00`。若按北京时间运行，在调度器显式配置 `Asia/Shanghai`，对应 cron `0 3 * * *`；不依赖机器默认时区。执行前确认凌晨事项不与 CI 或其他测试共用临时资源和端口。
- 在独立检出或工作目录中运行，使用已批准、已提交的版本；记录 `git rev-parse HEAD`、分支/来源、Node/npm 版本、开始时间与时区。不要将现有开发目录的未提交内容混入夜间结果。本地已验证但未提交的能力，不要算作夜间目标版本已覆盖。
- Node/npm 要求见 [README](../README.md#环境要求)。固定运行时版本；从仓库根目录用 `npm ci` 按锁文件安装，保留安装失败原因；不读入个人开发环境的 `.env.local`、浏览器登录态或历史凭据。
- 每轮生成唯一 `run_id`；同一目标版本通道只允许一轮在执行。建议首次落地设置 45 分钟整轮上限，并为等待服务、浏览器断言、SSE/WS 和外部轮询设置独立超时。到时停止等待、执行清理并报告，不同轮次不重叠。

### 2.2 运行现有门禁（A/B）

安装完成后，在仓库根目录逐条执行，分别保留退出码、用时和失败摘要；依赖不成立时跳过对应后续项，独立检查仍可执行。

```bash
npm ci
npm run lint --workspace=client
npm run test --workspace=client
npm run build --workspace=client
npm run test --workspace=server
npm run test:deployment
```

`test:deployment` 先运行 `npm run build --workspace=server`，无需在例行任务里重复构建；单独排查服务端编译时才另跑。`git diff --check` 可用于检查待交付补丁；在干净检出上它不能替代 lint 或测试。不要硬编码历史用例总数，以当前版本实际输出为准；发现未收集到测试应告警。

| 检查入口 | 重点断言 |
| --- | --- |
| `client/src/forwardApi.test.ts`、`templateConfig.test.ts`、`templateTools.test.ts`、`chatActions.test.ts` | 请求字段、分页及游标错误、结构化错误、SSE 帧处理、最小更新与隐藏字段保留、工具交互、停止终态及超时 |
| `client/src/{attachments,artifactPreview,markdown,multiagent,usageApi,credits,channelBinding}.test.*`、`client/src/voice/*.test.*` | 附件识别与下载路径、制品预览回退、Markdown、协作状态、用量口径、渠道绑定和语音客户端边界 |
| `server/src/httpProxy.test.ts`、`server/src/qca/adapter.test.ts`、`server/src/voiceProxy.test.ts` | SDK 参数和状态透传、真实 HTTP 模拟上游、请求级凭据、multipart、SSE 连接隔离与释放、WebSocket 来源验证与鉴权、错误码及请求 ID |
| `tests/voiceDeployment.test.ts`、`tests/voiceParity.test.ts` | 本地构建与 Vercel 导出入口的语音契约一致；不会部署，不验证线上运行环境或真实语音识别/合成 |

### 2.3 浏览器回归（C，接入后无人值守）

1. 在隔离目录运行 `npm run dev`，等待 `http://localhost:5173` 可打开、`http://localhost:3001/api/health` 返回 HTTP 200 且 `status: "ok"`。只复用本轮启动的进程。健康检查成功证明服务已启动，不证明上游可用。
2. 创建干净浏览器上下文；交互验收优先使用 `remote-browser-use`。自动跑须配置独立浏览器执行器、固定测试数据、请求记录和明确断言。使用假凭据并将 Forward/Cloud API、上传、SSE/WS 指向受控模拟；意外外部请求直接阻断，不能回退到生产。
3. 按下方 C 系列执行。本层记录页面行为、请求方法/路径、脱敏请求体和响应断言；不要用“按钮可见”代替写入回读。浏览器直接模拟请求的用例只证明 UI 契约，代理透传由 B 层验证。
4. 每个用例用独立数据或显式复位；检查非预期控制台错误、未处理拒绝、错误网络请求，失败时保留脱敏截图和请求摘要。主动注入的 4xx、5xx、断流只有在 UI 正确处置后才算通过。

### 2.4 真实上游冒烟（D，可选且独立开关）

- 先核对目标部署、环境和授权清单。`cn-prod` 与 `global-prod` 各用独立测试账号、凭据和资源；按批准的 PAT/Service Account 组合单独记结果。不要拿历史 PAT、生产用户、真实客户资源或业务群当测试数据。未获得真实 Beta 资格时记录 `SKIP`/`BLOCKED`，不以模拟结果替代。
- **默认只读**：检查目标部署、登录/授权、模型和测试资源列表、已知专用模板及测试历史详情（通过应用的登录可能自动创建 Identity；只读模式需使用预置 Identity，或只走不会自动创建的查询）。真实读取出现无权限、限流、配额不足或上游错误时保留原状态和 request ID，不自动升级权限或切换到其他环境。
- **仅在明确启用受控写入时**：使用独立测试账户、临时命名空间和每轮资源清单，设置并发、请求、Token/Credit 与耗时上限。走一次“测试模板 → 新 Session → 发送固定无敏感信息的测试指令 → SSE/终态 → 历史回读”，以事件顺序、用户消息、非空回复和终态为核心断言，不以普通模型文案逐字一致判失败。按需要再批准一次最小文件上传/下载或专用测试任务；不得把全量管理操作、真实 IM 投递或定时触发默认放进每日写入。
- 外部渠道配对、Webhook 投递、真实麦克风与音频、SA 特权、OSS、Beta 模型等走单独验收矩阵，只针对批准的沙箱对象。禁止重试结果未知的写入；先按本轮记录核验是否受理。对于文档、权限或上游行为尚待官方澄清的问题，单独记录环境、错误码、request ID、复现时间和影响，不编造兼容逻辑，也不擅自发送反馈。

## 4. 清理、报告和告警

- **清理**：无论成功、失败还是超时，都关闭本轮浏览器页面/上下文、停止本轮服务、移除假登录态与临时文件。真实写入按本轮资源清单逆依赖顺序清理（先停运行和定时触发，再解除绑定并清理临时资源）；只处理带本轮标记且归测试账号所有的对象。清理失败登记残留类型、安全引用和人工处置建议，不能静默略过。报告按配置保存期限清理。
- **每轮摘要**：记录 `run_id`、计划/开始/结束时间与时区、commit、环境、分层项状态、用例 ID、通过/失败/跳过/阻塞数、失败步骤与预期/实际、HTTP 错误码、request ID、脱敏证据链接、清理状态；不记录 PAT/SAT/SA Key、Authorization、签名链接、客户文件、未脱敏 HAR 或密钥截图。
- **告警触发**：必跑构建/lint/测试失败、已接入的核心浏览器链路失败、授权范围内真实冒烟失败、整轮未启动/超时、报告缺失或写入清理失败。建议另设独立看门狗，在约定完成时间未见该日结果时发「任务未完成」，避免执行器挂掉不告警。可选项长期跳过可汇总提醒，不伪装成回归失败。
- **告警接收与去重**：接入后由用户配置本人接收方、发送凭据和可重试策略；默认不发群。每轮按环境聚合，同类失败以 `仓库/环境/层级/用例/错误码` 合并；首次失败报告，连续同类失败只补次数或状态变化，恢复后发送一次恢复通知。告警发送失败用独立渠道或执行器状态暴露，不能记为已送达。
- **消息示例**：`[Forward 夜间巡检][失败] 03:00 Asia/Shanghai | commit=<sha> | B PASS / C FAIL (C08) / D SKIP | 断流后未恢复，request_id=<脱敏引用> | 清理完成 | 证据=<报告链接>`。实际首轮先验证失败、恢复及未启动三种通知，只发到选定的测试接收方。
