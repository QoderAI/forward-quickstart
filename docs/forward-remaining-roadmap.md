# Forward Quickstart 后续优化路线：第二至第五阶段

根据此前与官方 Forward 文档逐目录对照后的五阶段方案整理。保留原编号 **4–17**，方便下次直接按阶段或编号继续；编号表示实施顺序，不是缺陷严重程度。本文是待办，不代表这些能力已经实现、提交、发布或通过真实 API 验收。

**第一阶段是前置基线，不列入待办：**保护配置保存和 API 契约，修正 SSE 与取消/归档生命周期，补齐分页和最新详情。本地曾做自动化及模拟上游浏览器回归；第一阶段改动目前仍在本地工作区，开始第二阶段前应先确认要基于哪个提交、是否纳入这些改动，不能假定远程主干或生产已经包含。具体回归见[完整测试清单](./nightly-test-checklist.md)。

## 第二阶段｜补齐核心 Agent 体验

| 编号 | 优化方向 | 优化前的现状 | 优化后的预期与验收 |
| --- | --- | --- | --- |
| 4 | 完整模板与模型配置 | 有模型、effort、工具和基础资源；第一阶段能保留部分高级字段，但没有完整编辑入口 | 补充模型 `speed` 等受支持档位、工具轮数、Advisor 和 managed capabilities（如 Schedule/Drive）。创建或编辑后按最新详情回读核验；不同模型/环境支持的选项正确显示，不支持时明确提示；继续通过最小更新回归，不以新表单默认值覆盖旧配置。 |
| 5 | Identity 个性化与授权 | Identity 主要用于登录；缺按身份管理覆盖配置的界面；Identity SAT 有 API 封装但缺体验流程 | 两个测试 Identity 使用同一模板，分别呈现不同提示词、模型、工具与资源，能够查看生效配置、区分继承/覆盖并恢复继承。用身份绑定 Token 在测试范围验证同身份可访问、跨身份正常拒绝，不仅隐藏界面入口。 |
| 6 | Session 配置与交互事件 | 已支持聊天、挂附件、取消，以及现有审批/问题交互；缺完整会话更新、预算、通用工具结果和 Outcomes | 补充会话级配置覆盖和预算，让限制与达限反馈可见；演示「工具请求 → 外部结果 → Agent 继续」及「定义目标 → 查看评估结果」两条链路。对可更新状态、事件类型、失败/重试语义按官方契约核验，不重放写请求。 |
| 7 | 多 Agent 与 Threads | 父会话已有团队卡片、派发和回复展示；缺独立线程管理与完整线程历史 | 从父会话进入具体子线程，查看任务、独立分页历史、实时进度和结束状态；线程完成不关闭父 SSE，切换不串线程；管理操作仅在官方支持且获得授权时开放。 |

**阶段验收场景：**在同一测试模板下登录两个身份，确认各自差异和资源隔离；为其中一个会话设置预算、完成一次外部工具结果回填，随后打开子 Agent 线程并在刷新后还原结果。

## 第三阶段｜展示持久化与智能整理

| 编号 | 优化方向 | 优化前的现状 | 优化后的预期与验收 |
| --- | --- | --- | --- |
| 8 | Memory Store、Mount 与版本 | Demo 主要读取第一个关联 Store，缺创建、选择、挂载和维护入口 | 能按授权创建和选择 Store、挂载/卸载、区分只读/读写，查看内容版本并明确处理更新冲突。使用合成记忆数据，在两个独立会话中验证挂载后的可见性；无关联、无权限和空 Store 分开提示。 |
| 9 | Identity Drive | 已有 File 上传和会话挂载，没有 Identity Drive 浏览或管理 | 增加目录浏览、签名上传与下载、删除和清理；在同一 Identity 新建第二个会话后仍能打开上一会话保存的测试文件。验证目录边界、身份隔离，区分 Drive 持久文件与单会话临时文件。 |
| 10 | Dream | 无入口 | 对测试范围内的历史记忆和会话发起异步整理，展示运行状态、结果和整理前后差异；区分受理、成功、失败与超时；不能把“已提交”显示成“已整理”。依赖可用记忆与会话来源。 |
| 11 | Decisions | 无独立入口，只能经聊天取得自然语言回答 | 基于状态或会话上下文，展示结构化选项、评分、理由（若接口提供）以及错误。用固定场景校验结构和约束，不把不稳定的自然语言逐字比对当成通过标准。 |

**阶段验收场景：**会话 A 保存测试文件和记忆，会话 B 在同一身份下继续使用；发起一次整理、查看前后差异，再用测试上下文拿到可解析的结构化决策。另用第二个测试身份验证隔离。

## 第四阶段｜形成自动化业务闭环

| 编号 | 优化方向 | 优化前的现状 | 优化后的预期与验收 |
| --- | --- | --- | --- |
| 12 | Schedule 与 Run 历史 | 有基础定时任务；立即运行主要跳回聊天；缺完整执行与交付配置 | 支持官方提供的执行策略、资源、投递目标及自然语言管理。能从「触发时间 → 执行会话 → 运行状态 → 投递结果」逐步追溯；失败原因可诊断。以沙箱任务核验初始事件与最终执行，待官方澄清的行为单独记录。 |
| 13 | Channel Pairing | 已支持固定 Channel、扫码或手工授权；缺会话范围配对 | 增加在 IM 中按授权配对身份和模板、查看/解除绑定，验证消息与定时结果只路由到指定用户或群。使用专用测试渠道，未批准的联系人和群不参与。 |
| 14 | Webhook | 无管理与接收示例 | 能配置事件订阅，展示测试投递、接收记录、签名验证和去重；在受控端点证明同一事件不会重复处理，验签失败不进入业务逻辑。密钥和原始敏感载荷不出现在报告中。 |

**阶段验收场景：**隔离环境手动触发一条测试 Schedule，在 Run 历史看到触发和执行，核验测试 IM 目标和模拟 Webhook 各自的投递结果；没有审批时只做模拟验证，不发送真实外部消息。

## 第五阶段｜补齐全接口控制面

| 编号 | 优化方向 | 优化前的现状 | 优化后的预期与验收 |
| --- | --- | --- | --- |
| 15 | 资源高级管理 | 已有基础资源 CRUD；缺资源 Search、Skill Versions、Credential 更新及完整环境配置 | 可搜索资源、固定版本及升级 Skill、原位轮换 Credential；支持经官方契约确认的包、启动脚本、自托管或 OSS 环境配置，补齐 GitHub、A2A 配置体验。测试只用沙箱账号和资源，轮换后验证新配置生效与旧值保护，编辑不覆盖未管理字段。 |
| 16 | 身份与 Token 管理 | 缺完整身份控制台、统计和 Token 生命周期管理 | 支持身份列表/详情、启停、关联配置和统计，展示 Token 有效期、授权范围及撤销结果。对 `clear`、删除、撤销等不可逆或有影响的操作展示目标及影响范围并显式确认，仅在独立测试账户验收。与第 5 项区分：第 5 项先做个性化及身份授权体验，第 16 项补齐管理面。 |
| 17 | Batch、Voice、Usage 完善 | 都有基础主流程；逐任务参数、筛选、状态和展示仍不完整 | Batch 补充逐任务配置及校验结果；Voice 支持标题/metadata 的受支持管理与回读；Usage 补齐时间范围、Identity/Template 等查询组合，保持汇总与明细口径区别。不重做已有主链，回归分页、历史与权限。 |

**阶段验收场景：**按最新官方目录逐条核对剩余公开能力；分别演示 Skill 版本升级、专用凭据撤销、批次逐任务结果、语音 metadata 回读和多维用量查询。标记未开放、不适用或官方待澄清的项，不按页面数冒充接口覆盖率。

## 下次开始与每项完成标准

1. **确认范围与版本。** 从第二阶段开始最稳妥，优先第 4 项；只开发当次确认的编号，不因为选择一个阶段就自动修改其他阶段、提交、推送或部署。
2. **先核对官方文档和实际代码。** 对照同一时期的 [Forward 官方文档](https://docs.qoder.com/cloud-agents/api/forward/overview)、SDK 能力及现有入口，确认字段、权限、区域、Beta、错误语义；文档只读或账号不开放、以及需要官方确认的问题单列，不擅改、不臆造接口。
3. **按完整链路验收。** 每项至少具备可发现的入口、正确的请求与权限边界、可回读的结果/历史、空态与失败反馈、自动化和浏览器回归；模拟、真实上游和生产部署验收分别记录。若结果不可回读，写明官方支持的可验证证据。
4. **保留现有体验。** 普通用户模式保留对话和核心场景，高级配置放在开发者模式；真实授权依赖 Token 与服务端。完成后核对 README，并把新增用例纳入[测试清单](./nightly-test-checklist.md)。
